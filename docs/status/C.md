## 4. Design decisions and why (read before changing behaviour)

### 4.1 Clients and failover (`clients.ts`, `config/network.ts`)
- Presenter order: optional dedicated URL (`VITE_RPC_URL`, or pasted on `/ops`) -> QuickNode -> Monad Foundation -> Ankr, via viem `fallback(..., { retryCount: 1 })`. Spectator order is reversed (Ankr first) to spread venue-WiFi load. Every HTTP transport: `timeout` 4 s, `batch: false` (Monad Foundation rejects batch requests), `retryCount: 0`.
- A custom `shouldThrow` stops fallback for errors another RPC would repeat: revert (code 3), nonce too low, "already known", insufficient funds, reserve-balance. Transport trouble (429, timeouts, fetch failed) hops to the next RPC.
- The **send path has its own bundle** with a longer HTTP timeout (6 s) than the 4 s `eth_sendRawTransactionSync` server timeout, so the RPC answers before the client gives up.
- **A localhost `rpcOverride` replaces the public list entirely** (a fork can never leak onto the real testnet). The explorer URL is overridden to MonadVision (default) and Monadscan; viem's built-in `testnet.monadexplorer.com` is stale.
- Clients are built lazily and cached; importing `@/chain` has no side effects.

### 4.2 Keys (`keys.ts`)
- Priority: `sessionStorage['run.operatorPk' / 'run.backupPk']` then env `VITE_OPERATOR_PK` / `VITE_BACKUP_PK`. Node (tsx, vitest) reads `process.env`; the browser reads `import.meta.env` (so keys come only from a local `app/.env.local`; the Vercel build refuses to build with a `VITE_*PK` set; F verified the deployed bundle contains no key).
- Validation `^0x[0-9a-fA-F]{64}$`, normalises a missing prefix. Errors never echo input. `saveOperatorKeys` / `clearOperatorKeys` do nothing (no throw) when `sessionStorage` is missing or blocked. Keys are never written to `localStorage`.
- Only addresses are ever displayed (ChainLab, smoke output, preflight).

### 4.3 Live adapter send path (`liveAdapter.ts`)
1. **Serialised**: every write goes through one promise chain, so a UI `ping` cannot race a `sealTicks` for the nonce.
2. **Gas**: see 4.4.
3. **Signing**: `privateKeyToAccount(pk, { nonceManager })`; `prepareTransactionRequest` (EIP-1559, fee estimate cached 10 s); sign locally; hash = `keccak256(raw)`; the signed tx is kept in a `held` map keyed by calldata for 60 s.
4. **Send**: `eth_sendRawTransactionSync` with a 4 s timeout. If the RPC says the method is unsupported or rejects the parameters (-32601, -32602; anvil rejects the timeout param), the adapter remembers and uses `sendRawTransaction` + 200 ms receipt polling from then on.
5. **Timeout (code 4 or timeout message)**: look the receipt up by hash for ~2 blocks; if absent, **re-broadcast the same raw tx** (same hash, safe); wait up to 8 s more; then throw `ChainTimeoutError` **keeping the held tx**. The next call with identical calldata (the SealQueue resends the same batch) reuses it instead of signing a new one.
6. **Nonce too low / already known**: check for the receipt, otherwise reset the nonce manager and sign again once, silently. Any send that definitely failed also resets the nonce manager (no gaps).
7. **Receipt reverted**: replay the call at `blockNumber - 1`. A decoded RunBank error means a real revert (`RunBankRevert`, not retried). If the replay **succeeds**, the tx ran out of gas: retried once with **double the limit** (never lower than the limit that failed), and `gasMode` falls back to `'estimate'` for the rest of the run. (On Monad receipts always show `gasUsed == gasLimit`, so replay is the only way to tell.)
8. Decoding: `parseEventLogs` against the real ABI -> `RumorEvent`, `TickSealedEvent[]`, `OutcomeEvent`; Solidity `Status` 0..3 -> `'ready' | 'running' | 'failed' | 'survived'`.
9. `recoverTicks(from, to)`: rebuilds a `SealResult` for ticks that already landed, by walking `getLogs` backwards from head to the run's `startBlock` in <= 100-block chunks. Used by the SealQueue.
10. `gasLog`: one entry per `sealTicks` batch `{ ticks, ids, distinctSlots, estimate|null, formula, gasLimit, gasUsed, mode, txHash }`, also logged with `console.debug('[gas]', …)`.

### 4.4 Gas policy (`gasModel.ts` is A's; the policy is C's)
- **Default `gasMode = 'formula'` for `sealTicks` only**: limit = `gasLimitFor(ticks, { queued })` using A's **safe envelope** (no `speedBump` option) and `queued` = `queueLengthAfter` of the last sealed tick (0 after reset/startRumor/setLevel/outcome; refreshed from every snapshot read). No `eth_estimateGas` round trip. Measured on the real testnet (20-tick soak, same wallet, same hour): batch time mean **1.11 s -> 0.83 s**, median 1.08 -> 0.84, ticks per tx 2.86 -> 2.22, cost of the soak 0.134 -> 0.307 MON (about +0.2 MON per full run).
- **Why the envelope and not the tight level-0 fit**: the tight fit (`speedBump: false`) is about 5% below the one real sample that contains the failing tick (`{ticks 1, ids 137, slots 57, estimate 713,808}` vs fit 679,100). The failure path costs extra that does not scale with ids.
- **Fixed-cost calls always estimate** (`setLevel`, `startRumor`, `reset`, `ping`, `fundBank`): `estimateGas + 10%` through `estimateContractGas`, which also surfaces a revert (WrongStatus etc.) before anything is charged. If `estimateGas` fails for a transport reason (not a revert, not out-of-funds, not reserve-balance) the send uses A's fixed `callGas` (`setLevel` 380k, `startRumor` 160k, `reset` 160k) or 80k/120k for ping/fund, and for ticks the envelope.
- `adapter.gasMode = 'estimate'` (or `chain:smoke --gas estimate`) restores estimate + 10% for ticks too.
- Monad charges the gas **limit**, so oversized limits cost real MON; the numbers above are the trade-off.

### 4.5 SealQueue (`sealQueue.ts`, PRD §12.4)
- One transaction in flight; takes up to `maxTicksPerTx` (8) pending ticks. Duplicate or already-pushed ticks are dropped. After a timeout the **same batch** is resent (so the adapter can re-broadcast the same signed tx).
- Health: `sealing` while in flight; `delayed` when the oldest unsealed tick has waited > 2.5 s; `paused` after a revert/desync; `offline` when every RPC fails; `idle` otherwise.
- `TickMismatch` / `WrongStatus` recovery: read `snapshot().tick`. If the chain is at or past the batch's first tick, some or all of the batch already landed (a timed-out send that confirmed late): rebuild those ticks with `adapter.recoverTicks`, emit them, drop them from the queue, send only the remainder. If the chain is behind the batch, that is a real desync: pause with the "press Reset" error.
- Timeouts: up to `timeoutRetries` (3) silent retries (`delayed`), then pause with a **Retry** action. Offline: retries forever every 2 s; only if the outage lasts > 6 s does it emit one error (so the stage pauses with the replay hint).
- After the outcome event the rest of the queue is dropped (the contract ignores later ticks).
- Subscriber exceptions are swallowed so a UI bug cannot stall sealing.

### 4.6 Errors (`errors.ts`, PRD §12.6)
Every row of the table is implemented and tested, using viem error classes plus regex fallbacks. `extractRevert` reads a RunBank error from `RunBankRevert`, `ContractFunctionRevertedError`, `RawContractError`, **or the `data` field of a plain RPC error** (needed for `eth_call` replays). Strings never include raw hex blobs (anything `0x` + 40 hex chars or longer is replaced) or keys. `Underfunded` renders "The bank holds X AUSD but needs Y AUSD. …". Unknown errors: "Sealing failed: {short reason}. Press Retry, or Shift+R for the recorded run."

### 4.7 Preflight (`preflight.ts`, PRD §12.5)
Checks: each RPC (direct `eth_chainId` fetch, latency <= 800 ms), a summary RPC check (critical: at least one), block feed (a block within 2 s), operator key, operator MON (pass >= 15, warn 10.5 to 15, fail < 10.5), backup MON (non-critical), contract has code and `isOperator(active)`, bank status (warn unless `ready`), AUSD held >= `cash0 + bonds0` (counts Street while not ready), onchain `ledgerHash` equals the engine's, `configHash` equals `hashConfig(model.configs[level])` (warn only: it is set on switch), test `ping()` sealed within 2 s. Missing deployment or key produce `fail` with a plain sentence, never a throw. `ok` = no critical check failed. The mock adapter returns an all-pass report with `detail: "simulated"`. (Fonts / audio / window-size checks are F's and E's, not C's.)

### 4.8 Block feed (`blocks.ts`)
One shared subscription for any number of watchers (calling `watch` twice never subscribes twice): WSS `newHeads` on QuickNode; if the socket errors or goes quiet for 2 s, falls back to polling `getBlockNumber` every 400 ms; finalized height every 1 s. Local-fork overrides skip WSS. Verified: 17 blocks in 6 s through the WSS path.

### 4.9 Spectator (`spectator.ts`, PRD §12.7)
Polls every 1.2 s (`getLogs` for the bank address, chunks of <= 100 blocks, 3 in parallel), snapshot every 2 s. On first start looks back 2,000 blocks (or to `deployBlock`) for the newest `RumorStarted` with no later `BankReset` and replays it (rumor, its ticks, outcome if any) so a late joiner catches up. Dedupes by `blockNumber:logIndex`; backs off x2 up to x8 on any error (429); skips ahead instead of issuing thousands of calls after a long sleep. `start()` twice does not double the polling. Idle (no calls) while `deployment.runBank` is null.

### 4.10 Recorder and replays (`recorder.ts`)
`begin(params, rumor, modelHash)` sets t0 = the rumor receipt; `add(SealResult)` records tick payloads and seal timings relative to t0 (also for simulated records, with the zero hash); `finish(outcome)` returns the `ReplayFile` (PRD §16.1, bigints as strings). `listReplays` / `loadReplay` fetch `/replays/index.json` and `/replays/<id>.json`, tolerate a missing index, and validate `version === 1`.

## 6. The single-writer guard (`app/scripts/chain-lock.ts`)

Why: several processes (C's smoke runs, F's `live:e2e`, A's Foundry calibration) send transactions to the same RunBank, and earlier two of them collided ("EOA nonce changed unexpectedly", `runId` jumping from 2 to 27, interleaved resets).

`guardLiveBank({ agent, purpose, client, runBank, signer, status, isLocalRpc?, force?, maxMinutes?, log? })` returns `{ release(), nonce }` or throws `BankBusyError`:
1. **Lock file `/tmp/run-bank.lock`** (fixed path; JSON `{agent, purpose, pid, startedAt, expiresAt}`, default 20 min). Created atomically; a stale lock (dead pid or expired) is taken over; the lock is removed on exit, SIGINT, SIGTERM, and only by its owner pid.
2. **`LIVE BANK: <agent> until HH:MM`** in the first 12 lines of any `docs/status/*.md` from another agent, with HH:MM still ahead today. "LIVE BANK: none" and past times are ignored. `--force` skips only this check, never the lock.
3. **Mid-run check**: bank status is `running` and any bank event in the last 100 blocks (~40 s).
4. **`guard.nonce.run(() => adapter.x())`**: before every send it reads the wallet's pending nonce; if it moved without us it throws `NonceDriftError` instead of resyncing silently. `chain:smoke` then skips its cleanup reset (it must not send into someone else's run).
Local forks (`isLocalRpc`) are exempt. `live:e2e` (F) already uses it with the backup key.

Protocol when you need the live bank: (1) read the top of every `docs/status/*.md` for a `LIVE BANK:` line, (2) write your own line with an end time, (3) run through the guard, (4) set it back to `none`. Use `pnpm chain:fork` whenever a live send is not strictly needed.

## 10. Gotchas and things that look like bugs but are not

- **Monad receipts report `gasUsed == gasLimit`** (you pay the limit). Do not use `gasUsed` to calibrate or to detect out-of-gas; the adapter replays the call instead. On an anvil fork `gasUsed` is the real number, so fork logs differ from testnet logs.
- **anvil forks are slow on cold state.** `eth_estimateGas` for a level-1 `setLevel` or a big batch can take 10+ s on a fork (anvil fetches slots remotely) and hit the 4 s HTTP timeout. That is a fork artefact; the estimate fallback exists for it. First runs on a fresh fork take 10 to 14 s, repeats about 3 to 4 s. `--stress` on a fork can time out for the same reason.
- **anvil's `eth_sendRawTransactionSync`** rejects the integer timeout parameter with -32602; the adapter treats that as "unsupported" and falls back. That is why `chain:fork` can exercise the fallback without a flag, and `--no-sync` forces it.
- **vitest loads `app/.env.local`** (Vite env loading), so the real keys are visible to tests. `keys.ts` reads `process.env` first, and `keys.test.ts` blanks the env with `vi.stubEnv`; do not write a test that asserts on real env values, because a failing assertion prints them.
- **`SealQueue.onError` is not "something went wrong a moment ago"**; see section 3. Transient problems are visible only through `onHealth`.
- **A "paused" queue never drains.** Scripts must `stop()` the queue on `onError` (smoke does; it once hung for 11 minutes).
- **Reset from `Ready` reverts** on the real contract (`WrongStatus(Running, Ready)`). Only reset when the snapshot status is not `ready`.
- **After a run ends, a re-sent batch gets `WrongStatus`, not `TickMismatch`** (A's contract checks status first). The queue's recovery handles both.
- **`sealTicks` stops silently once the status leaves `Running`**; remaining ticks in the batch are ignored with no events. The returned `toTick` is the last tick actually applied.
- **The shared bank**: a smoke run resets it if it is not `ready`. Check for `LIVE BANK:` lines first (the guard does).
- **`pkill` by pattern is a bad idea** here (other agents' dev servers and anvils run on the same machine). Kill by exact pid.
- ChainLab reads keys from the same places as the app; it has no key-paste form (the `/ops` page, owned by E, does that through `saveOperatorKeys`).
